# コーポレートページレビュー

公開情報をもとに作成した**研修用モック**(`/ndb-renewal` など会社情報を扱うページ)をレビューする。
`/ndb-renewal` は本番サイトではない。会社情報の正確さと信頼感を最優先する。

- `$ARGUMENTS` 指定あり: そのパスを対象にレビューする
- `$ARGUMENTS` が空: `git diff` で `/ndb-renewal` 配下の未コミット変更を対象にする

## レビュー観点

1. **架空情報の混入(最重要)**
   - 数字・実績・取引先・制度・連絡先を創作していないか
   - 未確認情報を断定していないか。サンプルは「サンプル」と明記されているか

2. **会社情報の意味改変**
   - 公開メッセージの趣旨を変えていないか(言い換えは可、意味の改変は不可)
   - 既存サイトの HTML/CSS/JS のコピーになっていないか

3. **文言の信頼感**
   - 誇張・断定しすぎ・曖昧表現がないか。コーポレートとして自然なトーンか

4. **CTA の自然さ**
   - 文言と遷移先が一致しているか。`href="#"` のダミーリンクを使っていないか
   - 遷移は `<a>`、操作は `<button>` になっているか

5. **Next.js / React の保守性**
   - セクション単位で分割され、表示データが配列等に分離されているか
   - 色・グラデーションが CSS 変数で一元管理されているか(ハードコード重複がないか)
   - 共有 CSS/トークンの波及範囲がコメントされているか

6. **アクセシビリティ / レスポンシブ**
   - セマンティック HTML、見出し階層(h1 は1つ)、ランドマーク
   - フォーカス可視(`:focus-visible`)、カラーコントラスト、キーボード操作
   - スマホ幅でのはみ出し・隠れる要素

7. **テストの十分性**
   - ユーザーから見える文言と導線(CTA のリンク先など)を検証しているか
   - 文言変更にテストの期待値が追従しているか

## 報告フォーマット

CLAUDE.md の方針に合わせ、重要度で分けて日本語報告する。各指摘は「該当箇所(file:line) / 問題 / なぜ」を添える。

### ✅ 良い点
- 維持すべき実装

### 🚨 High
- 架空情報の混入、誤動作、アクセシビリティ必須要件など、優先して直すべき指摘

### ⚠️ Medium
- 直したいが範囲を限定できる指摘

### 💡 Low
- 任意の改善案

## 注意事項

- レビュー中に架空情報を補わない。不足は「未確認」として指摘する
- 会社情報の意味を変える提案や、見た目だけの作り替えは推奨しない
- まず提示し、修正は許可された範囲だけ最小変更で行う
- プロジェクトの CLAUDE.md(コーポレートサイト系ページの方針)を前提にする
